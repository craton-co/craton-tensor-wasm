# Shell completions for `tensor-wasm`

Committed scaffolding for the three shells the project supports as a v1.0 exit
criterion: **bash**, **zsh**, and **fish**. PowerShell and Elvish are
generatable via `tensor-wasm completions <shell>` but are not committed because
the project does not yet test against them in CI.

| Shell | File           | Generator                                     |
|-------|----------------|-----------------------------------------------|
| bash  | `tensor-wasm.bash`  | `clap_complete::Shell::Bash`                  |
| zsh   | `_tensor-wasm`      | `clap_complete::Shell::Zsh`                   |
| fish  | `tensor-wasm.fish`  | `clap_complete::Shell::Fish`                  |

> **Provenance.** Generated by `clap_complete` / `clap_mangen` from the canonical
> clap CLI definition; CI regenerates and diffs against the committed copy on
> every PR.

## Regenerating

Each script is regenerated independently. The `--out-dir` flag writes to the
conventional filename for the target shell (`tensor-wasm.bash`, `_tensor-wasm`,
`tensor-wasm.fish`) so you can refresh all three from the repository root with:

```bash
cargo run -p tensor-wasm-cli -- completions bash --out-dir crates/tensor-wasm-cli/completions
cargo run -p tensor-wasm-cli -- completions zsh  --out-dir crates/tensor-wasm-cli/completions
cargo run -p tensor-wasm-cli -- completions fish --out-dir crates/tensor-wasm-cli/completions
```

Or pipe to stdout if you'd rather diff manually:

```bash
cargo run -p tensor-wasm-cli -- completions bash > crates/tensor-wasm-cli/completions/tensor-wasm.bash
```

Either form is fine. CI runs the `--out-dir` variant and asserts the resulting
files match the committed copies.

## Installing

### bash

System-wide (requires root):

```bash
sudo cp crates/tensor-wasm-cli/completions/tensor-wasm.bash /etc/bash_completion.d/tensor-wasm
```

Per-user (no root):

```bash
mkdir -p ~/.local/share/bash-completion/completions
cp crates/tensor-wasm-cli/completions/tensor-wasm.bash \
   ~/.local/share/bash-completion/completions/tensor-wasm
```

On macOS with Homebrew bash-completion@2:

```bash
cp crates/tensor-wasm-cli/completions/tensor-wasm.bash \
   $(brew --prefix)/etc/bash_completion.d/tensor-wasm
```

Open a new shell — `tensor-wasm <Tab><Tab>` should now offer subcommands.

### zsh

The committed file is named `_tensor-wasm` per zsh convention. Drop it on
`$fpath` and `compinit` will pick it up:

```bash
mkdir -p ~/.zsh/completions
cp crates/tensor-wasm-cli/completions/_tensor-wasm ~/.zsh/completions/_tensor-wasm
# Then ensure ~/.zshrc has:
#   fpath=(~/.zsh/completions $fpath)
#   autoload -Uz compinit && compinit
```

On distros with a system-wide site-functions directory:

```bash
sudo cp crates/tensor-wasm-cli/completions/_tensor-wasm /usr/share/zsh/site-functions/_tensor-wasm
```

After installing, force a `compinit` reload (`rm -f ~/.zcompdump; compinit`) so
the new file is indexed.

### fish

Drop the file in the user's per-shell completions directory; fish discovers it
automatically:

```bash
mkdir -p ~/.config/fish/completions
cp crates/tensor-wasm-cli/completions/tensor-wasm.fish ~/.config/fish/completions/tensor-wasm.fish
```

System-wide (e.g. for a multi-user host):

```bash
sudo cp crates/tensor-wasm-cli/completions/tensor-wasm.fish \
        /usr/share/fish/vendor_completions.d/tensor-wasm.fish
```

No reload is needed; fish re-reads completions on demand.

## Verifying

```bash
tensor-wasm <Tab>            # should list: run, deploy, invoke, bench, snapshot, metrics, observe, completions, man
tensor-wasm run --<Tab>      # should suggest --export, --args, --tenant, --help
tensor-wasm snapshot <Tab>   # should list: save, restore
```

If your shell completes file paths instead of subcommands, the script has not
been picked up yet — open a fresh shell.
