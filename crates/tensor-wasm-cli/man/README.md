# Man pages for `tensor-wasm`

Committed roff(7) man pages — one for the root command plus one per top-level
subcommand. CI regenerates them on every change to the clap definitions and
diffs against the committed copies.

| File                          | Subject                                                       |
|-------------------------------|---------------------------------------------------------------|
| `tensor-wasm.1`               | Root command + global flags                                   |
| `tensor-wasm-run.1`           | `tensor-wasm run <FILE>`                                      |
| `tensor-wasm-deploy.1`        | `tensor-wasm deploy <FILE>`                                   |
| `tensor-wasm-invoke.1`        | `tensor-wasm invoke <ID>`                                     |
| `tensor-wasm-bench.1`         | `tensor-wasm bench <FILE>`                                    |
| `tensor-wasm-snapshot.1`      | `tensor-wasm snapshot save / restore`                         |
| `tensor-wasm-metrics.1`       | `tensor-wasm metrics`                                         |
| `tensor-wasm-observe.1`       | `tensor-wasm observe`                                         |
| `tensor-wasm-completions.1`   | `tensor-wasm completions`                                     |
| `tensor-wasm-man.1`           | `tensor-wasm man` (this generator)                            |

> **Provenance.** Generated by `clap_complete` / `clap_mangen` from the canonical
> clap CLI definition; CI regenerates and diffs against the committed copy on
> every PR.

## Regenerating

```bash
cargo run -p tensor-wasm-cli -- man --out-dir crates/tensor-wasm-cli/man
```

That single invocation writes the root page plus one per subcommand into
`crates/tensor-wasm-cli/man/`. CI runs the same command and fails if the
working tree drifts.

To preview a single page without committing:

```bash
cargo run -p tensor-wasm-cli -- man | man -l -
```

(`man -l -` reads roff from stdin on modern man-db; on macOS/BSD use
`groff -mandoc -Tutf8 | less`.)

## Installing

### Linux (Debian/Ubuntu/Fedora/Arch)

System-wide, into the standard man-db tree:

```bash
sudo install -d /usr/local/share/man/man1
sudo install -m 0644 crates/tensor-wasm-cli/man/*.1 /usr/local/share/man/man1/
sudo mandb            # rebuild the index so `man tensor-wasm` works
```

Per-user (no root, requires `~/.local/share/man` on `MANPATH`):

```bash
mkdir -p ~/.local/share/man/man1
cp crates/tensor-wasm-cli/man/*.1 ~/.local/share/man/man1/
# Ensure ~/.local/share/man is on MANPATH; many distros already cover this.
```

### macOS

```bash
mkdir -p /usr/local/share/man/man1
cp crates/tensor-wasm-cli/man/*.1 /usr/local/share/man/man1/
# macOS does not need mandb; `man tensor-wasm` should resolve immediately.
```

If you use Homebrew bash on Apple Silicon, the prefix is `/opt/homebrew/share/man/man1`.

### Windows

There is no native `man` tooling on Windows. Two reasonable options:

1. **WSL.** Inside the WSL distro, follow the Linux instructions above.
2. **Manual rendering.** Use `groff` (in MSYS2 or Cygwin) to render to text or
   HTML:

   ```powershell
   groff -mandoc -Tutf8 crates\tensor-wasm-cli\man\tensor-wasm.1 | less
   groff -mandoc -Thtml crates\tensor-wasm-cli\man\tensor-wasm.1 > tensor-wasm.html
   ```

## Verifying

After install:

```bash
man tensor-wasm          # root page
man tensor-wasm-snapshot # subcommand page
apropos tensor-wasm      # should list every committed page
```
